# ۳۵ جملهٔ پایانی

هر درس با یک جملهٔ «در یک جمله» تمام می‌شود. این فایل همان ۳۵ جمله را جدا از متن، به‌عنوان یک اثر مستقل، کنار هم می‌گذارد. اگر این جمله‌ها پشت سر هم خوانده شوند، باید خلاصهٔ کامل سند را بسازند.

| درس | عنوان | در یک جمله |
|---|---|---|
| ۱.۱ | هوش مصنوعی امروز واقعاً چه کاری می‌کند | هوش مصنوعی امروز در نوشتن، پاسخ از اسناد، کدنویسی و زنجیره‌کردن کارها خوب است؛ در دقت تضمین‌شده، نوآوری واقعی و کار بدون نظارت، نه. |
| ۱.۲ | یک نقشه برای همهٔ واژه‌ها | نقشهٔ درس‌ها در فهرست است؛ هر درس و واژه، راهی مستقیم به توضیح خودش دارد. |
| ۱.۳ | سه لایه: مدل، چارچوب اجرا، محصول | مدل فقط متن می‌سازد؛ چارچوب اجرا آن را به کار می‌اندازد؛ محصول چیزی است که شما می‌بینید. |
| ۱.۴ | مثالی که تا آخر همراه ماست | یک فروشگاه آنلاین و یک پرسش ساده، مثال مشترک همهٔ بخش‌های این سند است. |
| ۱.۵ | این سند چطور خوانده می‌شود | فقط اسکرول کنید؛ برای جابه‌جایی، نقشهٔ درس‌ها در فهرست است؛ بازکردن هیچ چیز برای فهمیدن لازم نیست. |
| ۲.۱ | از چت‌بات به ایجنت | چت‌بات فقط پاسخ می‌دهد؛ ایجنت تصمیم می‌گیرد چه کاری انجام دهد و نتیجه را می‌بیند. |
| ۲.۲ | ابزارها: چطور مدل کاری انجام می‌دهد | مدل فقط درخواست اجرای ابزار را می‌سازد؛ اجرا، بررسی و بازگرداندن نتیجه کار چارچوب اجراست. |
| ۲.۳ | MCP: پریز استاندارد ابزارها | MCP تعداد اتصال‌ها را از N×M به N+M کم می‌کند؛ استاندارد است، نه مجوز. |
| ۲.۴ | مهارت‌ها: دستورهای بسته‌بندی‌شده | ابزار دسترسی و اجرا می‌دهد؛ مهارت دستور و روش می‌دهد. |
| ۲.۵ | حافظه: چرا مدل شما را یادش نمی‌آید | مدل حافظه ندارد؛ حافظه را سیستم اطراف می‌سازد و هر بار بخشی از آن را به مدل می‌دهد. |
| ۲.۶ | ورک‌فلو یا ایجنت؟ | اگر مسیر روشن و خطا گران است، ورک‌فلو بسازید؛ اگر مسیر بسته به شرایط عوض می‌شود، ایجنت. |
| ۲.۷ | ایجنت‌های برنامه‌نویسی | ایجنت‌های برنامه‌نویسی زودتر جواب دادند چون تست، سیگنال درست و غلطِ ارزان می‌دهد. |
| ۲.۸ | یک ایجنت از چه ساخته شده | یک ایجنت از مدل، ابزار، مهارت، حافظه و یک حلقه ساخته می‌شود؛ ضعف هر قطعه، ضعف کل سیستم است. |
| ۳.۱ | مدل زبانی چه کار می‌کند: حدس کلمهٔ بعدی | مدل در هر قدم فقط احتمال کلمهٔ بعدی را می‌سنجد و یکی را انتخاب می‌کند؛ بقیهٔ رفتار از همین ساده بیرون می‌آید. |
| ۳.۲ | توکن: واحد کار مدل | مدل با توکن کار می‌کند، نه با کلمه؛ صورت‌حساب و محدودیت‌ها با توکن شمرده می‌شوند. |
| ۳.۳ | کانتکست: هر چیزی که مدل می‌بیند | مدل فقط همین بستهٔ متن را می‌بیند؛ وقتی بسته پر شود، قدیمی‌ترین بخش‌ها بیرون می‌افتند. |
| ۳.۴ | مدل چطور ساخته می‌شود: سه مرحله | پیش‌آموزش زبان و دانش عمومی می‌سازد؛ فاین‌تیونینگ رفتار را عوض می‌کند؛ هم‌راستاسازی آن را مفید و بی‌خطرتر می‌کند. |
| ۳.۵ | توهم: چرا مدل چیزی از خودش می‌سازد | توهم ادامهٔ روانِ بی‌پشتوانه است؛ مدل برای باورپذیری آموزش دیده، نه برای راست‌گویی تضمین‌شده. |
| ۳.۶ | مدل‌ها در چه چیزهایی ضعیف‌اند | مدل در شمارش، حساب، رویدادهای تازه، زنجیره‌های طولانی و سنجش اطمینان خودش ضعیف است؛ برای هر کدام یک ابزار بیرونی لازم است. |
| ۳.۷ | استدلال، و چرا مدل‌ها متفاوتند | استدلال یعنی خرج‌کردن محاسبهٔ بیشتر هنگام پاسخ؛ سه مدل مختلف سه نقطهٔ مختلف روی مثلث کیفیت، سرعت و قیمت‌اند. |
| ۴.۱ | یک فراخوانی API از نزدیک | هر فراخوانی یک درخواست مستقل است: مدل، پیام‌ها و تنظیم‌ها می‌فرستید و متن، دلیل پایان و مصرف را می‌گیرید. |
| ۴.۲ | پرامپت: دستور دادن مؤثر | پرامپت خوب نقش، کار، محدودیت و نمونه را روشن می‌کند؛ ولی هیچ پرامپتی جای کانتکست درست را نمی‌گیرد. |
| ۴.۳ | کانتکست: مهم‌تر از پرامپت | کار اصلی، چیدن درست کانتکست است: دستور سیستم، تاریخچه، اسناد مرتبط و پرسش، با رعایت ظرفیت کانتکست. |
| ۴.۴ | RAG: پاسخ از اسناد شما | RAG اول سند مرتبط را پیدا می‌کند، بعد آن را به کانتکست اضافه می‌کند و تازه پاسخ می‌سازد؛ جای حافظهٔ مدل را نمی‌گیرد، جای آن را پر می‌کند. |
| ۴.۵ | چه زمانی فاین‌تیون، چه زمانی RAG | برای دانشِ تازه و متغیر، RAG؛ برای رفتار و سبکِ ثابت، فاین‌تیون؛ و همیشه از ارزان‌ترین پله شروع کنید. |
| ۴.۶ | ارزیابی: چطور بفهمیم بهتر شد | ارزیابی یعنی یک مجموعهٔ ثابت از نمونه‌ها با پاسخ درست؛ میانگین را نگاه نکنید، پس‌رفت‌ها را جدا کنید. |
| ۴.۷ | از نمونه به محصول | دمو شروع کار است؛ محصول یعنی ارزیابی، محافظت، پایش، کنترل بودجه، مدیریت خطا و بازبینی انسانی. |
| ۵.۱ | معماری یک سیستم واقعی | سیستم واقعی یک مدل تنها نیست: دروازه، هماهنگ‌کننده، مدل، اسناد، ابزارها، حافظه و ثبت رخدادها کنار هم کار می‌کنند. |
| ۵.۲ | هزینه: پول کجا می‌رود | هزینه از توکن ورودی و خروجی می‌آید؛ سه اهرم اصلی، کوتاه‌کردن کانتکست، انتخاب مدل مناسب و کش‌کردن بخش‌های تکراری است. |
| ۵.۳ | امنیت: تزریق پرامپت و نشت داده | تزریق پرامپت را نمی‌توان کامل بست؛ با کمترین دسترسی، گاردریل و تأیید انسانی مهارش می‌کنید. |
| ۵.۴ | اتکاپذیری و مشاهده‌پذیری | در سیستم غیرقطعی، ردگیری گام‌به‌گام و مشاهده‌پذیری یعنی دیدن کانتکست، فراخوانی‌ها، تأخیر و نتیجهٔ هر درخواست. |
| ۶.۱ | کجا ارزش واقعی هست | اولین کاربرد را از جایی شروع کنید که کار تکراری زیاد است و خطا قابل جبران؛ نه از جایی که هیجان‌انگیزتر است. |
| ۶.۲ | بسازیم یا بخریم | اگر قابلیت تمایزآفرین نیست بخرید؛ اگر دادهٔ یگانه و تیم دارید بسازید؛ در بیشتر موارد، ترکیب کنید. |
| ۶.۳ | تیم و مهارت‌ها | تیم لازم چهار نقش است: مالک محصول، خبرهٔ حوزه، مهندس هوش مصنوعی و پلتفرم/امنیت؛ فقط بخشی از مهارت‌ها تازه است. |
| ۶.۴ | نقشه، یک بار دیگر | مدل حدس می‌زند، چارچوب اجرا می‌گرداند، کانتکست محدود است، RAG زمین می‌دهد، ارزیابی می‌سنجد و گاردریل مهار می‌کند؛ تصمیم نهایی با شماست. |
