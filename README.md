# هوش مصنوعی؛ از شناخت تا کاربرد

یک سند فارسی، تعاملی و تک‌فایلی برای کسانی که می‌خواهند هوش مصنوعی را بفهمند و به‌درستی استفاده کنند.
مسیر آن **شناخت و ایجنت‌ها ← استفادهٔ مؤثر ← بازکردن جعبه و فهم فنی** است. خروجی نهایی `dist/index.html` است: یک فایل مستقل
که بدون شبکه، از روی فلش یا پیوست ایمیل باز می‌شود.

## نسخهٔ آنلاین

نسخهٔ منتشرشدهٔ سند: <https://mahdilotfi167.github.io/ai-lectures/>

این نسخه همان `dist/index.html` است که روی GitHub Pages میزبانی می‌شود. چون همهٔ
دارایی‌ها درون فایل درون‌خطی شده‌اند، تنظیم `base` در Astro لازم نیست و سند هم در
ریشهٔ دامنه و هم به‌صورت محلی کار می‌کند.

## باز کردن سند به‌صورت آفلاین

`dist/index.html` را در مرورگر باز کنید. هیچ سرور، نصب یا اتصالی لازم نیست.
همهٔ فونت‌ها، شکل‌ها، استایل‌ها و اسکریپت‌ها داخل همان یک فایل هستند؛ می‌توانید
همین یک فایل را روی فلش کپی کنید یا به ایمیل پیوست کنید و بدون اینترنت باز کنید.

### ادامهٔ مطالعه از محل قبلی

محل مطالعه خودکار در مرورگر ذخیره می‌شود. وقتی همان فایل را دوباره در همان مرورگر
باز کنید، به همان بخش و نقطهٔ متن برمی‌گردید. ذخیره‌سازی فقط روی دستگاه شماست؛
نه شبکه‌ای لازم است و نه خود فایل HTML تغییر می‌کند.

پیوند مستقیم به یک درس بر محل ذخیره‌شده اولویت دارد. بازخوانی همان صفحه، محل دقیق
مطالعه را بازیابی می‌کند. تغییر اندازهٔ صفحه با توجه به محل نسبی شما در متن محاسبه می‌شود.
جابجایی یا تغییر نام فایل، مرورگر دیگر، پاک‌کردن داده‌های مرورگر یا پایان حالت خصوصی
ممکن است محل ذخیره‌شده را از دسترس خارج کند. اگر مرورگر ذخیره‌سازی فایل‌های محلی را
مسدود کرده باشد، سند همچنان خواناست، اما محل مطالعه ماندگار نمی‌شود.

شناسهٔ درس و شکل اکنون از شمارهٔ نمایشی جداست؛ مثلاً `#lesson-skills` همیشه به مهارت‌ها می‌رود.
پیوندهای عددی نسخهٔ قبلی به همان موضوع قبلی می‌رسند، نه درس تازه‌ای با شمارهٔ تکرارشده.
محل ذخیره‌شدهٔ نسخهٔ قبلی به ابتدای درس متناظر منتقل می‌شود؛ پس از آن، محل دقیق با قالب نسخهٔ دوم ذخیره می‌شود.

## مسیر یادگیری

1. **شناخت اولیه — بخش‌های ۱ و ۲:** تصویر کلی، محصول و مدل، ایجنت، ابزار، مهارت، تاریخچه و حافظه.
2. **استفادهٔ مؤثر — بخش‌های ۳ و ۴:** انتخاب کار و قابلیت، اشتراک امن، درخواست روشن، گفت‌وگو، بررسی، اختیار و بازیابی.
   درس **۴.۶** یک نمونهٔ کامل و کارت همراه دارد و نقطهٔ پایان مستقل مسیر عملی است.
3. **فهم پشت‌صحنه — بخش‌های ۵ و ۶:** مدل، توکن، ظرفیت کانتکست، API، MCP، RAG، ارزیابی، امنیت و تصمیم‌های فنی.

دانستن برنامه‌نویسی، داشتن حساب پولی یا اجرای مدل زنده برای دنبال‌کردن درس‌ها لازم نیست.

## ساخت مجدد

```bash
npm ci
npm run build
```

`npm run build` این کارها را انجام می‌دهد:

1. `scripts/check-skeleton.ts` — ۴۱ درس، سه مرحله، شناسه‌های پایدار، ترتیب، فراداده، شکل‌ها و لنزهای کانتکست را می‌سنجد.
2. `scripts/check-glossary.ts` — قواعد واژه‌نامه را اجرا می‌کند: `not_before`، نخستین کاربرد،
   لاتین ناشناس و وضعیت تأیید.
3. `scripts/check-context.ts` — دادهٔ لنزها را می‌سنجد: گشایش نوع بلوک‌ها، متن روایت،
   JSON، ثابت‌های داستان، سقف کنترل‌ها و تطابق فراداده با بدنه.
4. `astro build` — سند را می‌سازد و با `vite-plugin-singlefile` همه‌چیز را در
   `dist/index.html` درون‌خطی می‌کند.
5. `scripts/check-budget.ts --post` — بودجهٔ واژه و اندازهٔ خروجی را می‌سنجد و
    بررسی می‌کند که `dist` فقط یک فایل داشته باشد.
6. `scripts/check-output.ts` — یکتایی شناسه‌ها، مقصد پیوندهای داخلی و همهٔ نام‌های مستعار نسخهٔ قبل را بررسی می‌کند.

`npm test` آزمون‌های واژه‌نامه، نگاشت درس‌ها، ترتیب شواهد و مهاجرت محل مطالعه را اجرا می‌کند.

برای توسعه:

```bash
npm run dev
npm run check
```

## ساخت و انتشار خودکار

گردش‌کار `.github/workflows/pages.yml` این کارها را انجام می‌دهد:

- با هر `push` به `master`، هر pull request به `master` و اجرای دستی
  (`workflow_dispatch`) اجرا می‌شود.
- روی Node.js 24 (نسخهٔ LTS) با `npm ci` نصب و با `npm run build` می‌سازد.
  بررسی‌های `prebuild` و بررسی بودجهٔ پس از ساخت هم در همین مرحله اجرا می‌شوند.
- فقط خروجی `dist` را که همان `dist/index.html` است به‌عنوان artifact صفحه‌ها
  بارگذاری می‌کند.
- انتشار فقط برای `push` به `master` یا اجرای دستی روی `master` انجام می‌شود و
  از محیط `github-pages` با مجوزهای محدود `pages: write` و `id-token: write`
  استفاده می‌کند. pull requestها فقط ساخته می‌شوند و منتشر نمی‌شوند.

برای فعال‌کردن انتشار، در GitHub به `Settings → Pages` بروید و در بخش
`Build and deployment` گزینهٔ `Source` را روی `GitHub Actions` بگذارید. نیازی به
شاخهٔ `gh-pages` یا تنظیم `base` نیست.

## نوشتن یک درس

هر درس یک فایل MDX در `src/content/lessons/` است. فراداده با
`src/content.config.ts` اعتبارسنجی می‌شود. ساختار بدنه:

```mdx
یک پاراگراف قلاب که مسئله را می‌سازد.

<ComponentName id="fig-skills" caption="..." desc="..." ... />

متن توضیح مکانیزم.

<Takeaway>جملهٔ پایانی.</Takeaway>
```

قواعد مهم:

- شکل‌ها با داده به کامپوننت داده می‌شوند؛ SVG دستی در درس نوشته نمی‌شود.
- درس ۶.۱۲ شکل اصلی ندارد؛ به نقشهٔ فهرست ارجاع می‌دهد. فیلد `figure` اختیاری است.
- درس نقشه و راهنمای خواندن حذف شده‌اند؛ بخش اول سه درس از ۱.۱ تا ۱.۳ دارد.
- `caption` باید همان `figure.caption_fa` در فراداده باشد و *نکتهٔ* شکل را بگوید.
- `desc` توصیف واقعی شکل برای خوانندهٔ صفحه‌خوان است، نه تکرار caption.
- واژه‌ها در نخستین کاربرد با `<Term id="..." />` می‌آیند؛ بعد از آن شکل کوتاه.
- شناسه‌های لاتین داخل متن با `<Ltr inline>` ایزوله می‌شوند.
- ارقام متن فارسی‌اند؛ ارقام لاتین فقط در کد و جدول‌های اندازه‌گیری.

## فهرست و نقشهٔ ناوبری

دکمهٔ ثابت فهرست، نقشه‌ای با شش ناحیهٔ رنگی و برچسب سه مرحله باز می‌کند. همهٔ ۴۱ درس و مفاهیم واژه‌نامه
پیوند مستقیم دارند. جست‌وجو با نام فارسی یا انگلیسی، شمارهٔ درس و ارقام فارسی کار می‌کند.
درس جاری مشخص است؛ انتخاب یک مقصد، فهرست را می‌بندد و تمرکز را به محتوای مقصد می‌برد.

نقشه دیگر در درس‌ها یا ابتدای بخش‌ها تکرار نمی‌شود. نمایش آن در
`src/components/shell/TocMap.astro` و رفتار آن در `src/scripts/toc.ts` است.
بدون جاوااسکریپت، همان پیوندها در یک فهرست جمع‌شوندهٔ بومی در دسترس‌اند.


## لنزهای کانتکست

مثال مشترک درس‌ها، یک دستیار برنامه‌نویسی مثل OpenCode یا Hermes است:
شناخت کدبیس، افزودن قابلیت، اصلاح خطا، ویرایش فایل، اجرای کامند و بازبینی تغییرها.
مثال‌ها به یک پروژهٔ خیالی یا خطای خاص محدود نیستند. قطعه‌های کوچک مثل خواندن
`src/utils.ts` یا افزودن دارک مود، فقط برای روشن‌کردن سازوکار استفاده می‌شوند.
نام ابزارها آموزشی است، نه قرارداد واقعی یک محصول. دادهٔ نمونه در
`src/data/context/story.ts` است و فراداده با `example: coding` مشخص می‌شود.

درس ۱.۲ ترتیب پیام‌های `system → user → assistant → user → assistant` را در یک گفت‌وگوی دو نوبتی نشان می‌دهد.
در این کتاب، **نوبت** از پیام تازهٔ شما تا پاسخ نهایی دستیار است؛ یک نوبت می‌تواند چند فراخوانی مدل داشته باشد.
دستور سیستم نوبت نیست و `assistant` نقش پیام دستیار است، نه بازیگری جداگانه.
ورودی هر فراخوانی از پاسخ تازه جداست؛ پاسخ پس از تولید به تاریخچه می‌رود.
همان مثال در درس ۶.۱ به آرایهٔ `messages` نگاشت می‌شود؛ متن مشترک در
`src/data/context/conversation.ts` است. درس ۲.۴ تاریخچهٔ پیام‌ها را از یادداشت حافظه جدا می‌کند.

نمودارهای ترتیبی سه بازیگر دارند: **کاربر، ایجنت و مدل**. چارچوب اجرا و ابزارها
در ستون ایجنت‌اند. خواندن فایل و بررسی دسترسی کار داخلی ایجنت است؛ مدل فقط درخواست
ابزار یا متن پاسخ را به ایجنت برمی‌گرداند. ایجنت نتیجهٔ ابزار را در فراخوانی بعدی
به مدل می‌دهد و پاسخ نهایی را به کاربر می‌رساند.

بارگذاری مهارت در درس ۲.۳ پنج گام دارد: فهرست نام و توضیح و مسیر، درخواست خواندن توسط مدل،
خواندن توسط ایجنت، برگشتن متن مهارت به کانتکست بعدی و تصمیم بعدی مدل. فایل مهارت خودبه‌خود
ظاهر نمی‌شود و خواندن آن، به‌معنی اجرای تست یا تغییر کد نیست. دادهٔ جفت‌های درخواست و نتیجه
در `src/data/context/traces.ts` مشترک است. درس ۲.۶ اجرای تست ناموفق و تست دوباره را جدا نگه می‌دارد؛
درس ۶.۸ نتیجهٔ رد دسترسی را به مدل برمی‌گرداند و درخواست را از تاریخچه پاک نمی‌کند.

بیست درس یک **لنز کانتکست** دارند و درس ۶.۲ یک **آزمایشگاه کانتکست**. لنز، شکل دوم همان درس است
(شکل اصلی را عوض نمی‌کند) و نشان می‌دهد مدل در آن لحظه دقیقاً چه متنی می‌بیند، هر تکه را چه کسی
نوشته، و مدل چه ادامه‌ای می‌نویسد. جملهٔ پایانی همهٔ لنزها یکی است:
«مدل فقط ادامهٔ متنی را می‌نویسد که جلویش گذاشته‌اند.»

برای افزودن یا عوض‌کردن یک لنز:

1. بلوک‌های داستان را در `src/data/context/blocks.ts` تعریف یا ویرایش کنید (متن، نوع، توکن تقریبی).
2. لنز را در `src/data/context/lenses.ts` بسازید: `key`، `lesson`، `mode` و گام‌ها. اگر نوع بلوک
   تازه‌ای لازم است، آن را در `src/data/context/kinds.ts` با `introducedIn` درست اضافه کنید.
3. در فرادادهٔ درس `context_lens` را بنویسید و در بدنه، بعد از متن توضیحی و پیش از
   `<Takeaway>`، `<ContextLens ... />` را صدا بزنید (برای ۶.۲: `<ContextLab ... />`).
4. `node scripts/check-context.ts` را اجرا کنید. این ابزار مطمئن می‌شود هیچ واژه‌ای پیش از
   `not_before` نیامده، JSON معتبر است و گام‌ها روایت یک‌جمله‌ای دارند.

لنزها فقط یک نمای خواندنی دارند: هر بلوک یک برچسب کوتاه فارسی و متن اصلی دارد.
نوار بازیگران، برچسب نقش لاتین، آیکون و شمارش توکنِ تک‌تک بلوک‌ها حذف شده‌اند؛
تغییرهای مهم، حذف متن و هشدارها همچنان مشخص‌اند. اجرای ابزار، جست‌وجو و نوشتن حافظه
در یادداشت کوتاه «بیرون از متن» می‌آید و ادامهٔ مدل در کادری جدا، یک‌جا نشان داده می‌شود.
خروجی‌ها نمونهٔ ساخته‌شده‌اند، نه خروجی مدل زنده؛ مستقیم نمایش داده می‌شوند و پرسش چندگزینه‌ای یا آزمون ندارند. بدون JS، چاپ و کاهش حرکت،
همهٔ گام‌ها با هم نشان داده می‌شوند. شمارش توکن فقط برای نمایش ظرفیت و مجموع آزمایشگاه می‌آید.

آزمایشگاه نمای ورودی ازپیش‌آماده‌شده است، نه اجرای زندهٔ بارگذاری. متن مهارت و راهنما را برنامه
از قبل آماده کرده است؛ کلیدها فقط حضور آن‌ها را انتخاب می‌کنند. فهرست ابزارها به‌تنهایی پشتوانهٔ
شناخت کد نیست. با ابزار و مسیر فایل، درخواست خواندن و نتیجهٔ فایل، سپس درخواست تست و نتیجهٔ
ناموفق نمونه، کنار هم دیده می‌شوند. پاسخ برنامهٔ پیشنهادی است؛ هیچ کدی واقعاً اجرا یا منتشر نمی‌شود.
کشف فهرست MCP و مسیر RAG خودکار، آماده‌سازی برنامه پیش از مدل‌اند؛ این‌ها درخواست حذف‌شدهٔ مدل نیستند.

## واژه‌نامه و اعتبارسنجی

`glossary.yml` منبع واحد واژه‌هاست. هر واژه `not_before` دارد؛ استفاده پیش از
معرفی، ساخت را متوقف می‌کند. `check-glossary.ts` چهار قاعده را اجرا می‌کند:

1. `not_before` — واژه پیش از درس معرفی، در متن نیاید.
2. نخستین کاربرد — در درس معرفی با `<Term>` بیاید و بعداً دوباره gloss نشود.
3. لاتین ناشناس — هر توکن لاتین ≥۳ حرف باید در واژه‌نامه یا `allowed-latin.txt` باشد.
4. تأیید — با `--require-confirmed` هر واژه باید `status: confirmed` باشد.

## گالری شکل‌ها

`src/pages/_figures-gallery.astro` یک صفحهٔ توسعهٔ اختیاری است و در ساخت نهایی
شرکت نمی‌کند (نام فایل با `_` شروع می‌شود). برای دیدنش موقتاً آن را به
`src/pages/figures-gallery.astro` کپی کنید، `npm run dev` را اجرا کنید و بعد از
بررسی حذفش کنید. این صفحه شکل‌های پایه و گفت‌وگوی مرتب را با دادهٔ نمونه و یک کلید شبیه‌سازی
«کاهش حرکت» نشان می‌دهد. برای دیدن پنج حالت لنز، همین کار را با
`src/pages/_context-gallery.astro` تکرار کنید.

## دسترس‌پذیری و چاپ

- سند با JS خاموش هم خواناست؛ شکل‌ها و همهٔ گام‌های لنز در حالت نهایی‌اند و کنترل‌ها پنهان.
- `prefers-reduced-motion: reduce` همهٔ حرکت‌ها را حذف می‌کند و شکل‌ها را کامل نشان می‌دهد.
- `src/styles/print.css` نسخهٔ A4 می‌سازد: نوار پیشرفت و کنترل‌ها پنهان،
  فهرست پنهان، شکل‌ها در حالت نهایی، همهٔ گام‌های لنز باز و کدها روشن.
- برای PDF: در کروم `Print → Save as PDF` یا:
  ```bash
  google-chrome --headless --print-to-pdf=dist/book.pdf --no-pdf-header-footer file://$PWD/dist/index.html
  ```

## وضعیت محتوا

۴۱ درس، ۳ مرحله، ۶ بخش، ۴۰ شکل اصلی (۷ تعاملی)، ۲۰ لنز کانتکست و یک آزمایشگاه در مسیر تازه قرار دارند.
واژه‌نامه ۵۰ واژه و در وضعیت `confirmed` است. متن فارسی با مثال ایجنت برنامه‌نویسی بازنویسی شده است؛
بودجه‌ها سقف‌اند، نه سهمیه، و `check-budget.ts` فقط عبور از سقف را خطا می‌داند.
هدف اندازهٔ خروجی ۱٫۵ مگابایت است؛ اندازهٔ دقیق هنگام بررسی بودجهٔ پس از ساخت گزارش می‌شود.
