هر ابزار جدید برای هر برنامهٔ جدید یک اتصال تازه می‌خواهد. سه برنامه و چهار ابزار یعنی دوازده اتصال؛ با ده برنامه و بیست ابزار، کار به دویست اتصال می‌رسد. این روش مقیاس نمی‌گیرد. راه‌حل، یک استاندارد مشترک است: <Term id="mcp" />.

بدون استاندارد، برای هر ترکیب برنامه و ابزار باید یک اتصال جداگانه نوشت و نگه داشت. با یک استاندارد، هر ابزار یک بار تعریف می‌شود و هر برنامه‌ای که آن استاندارد را می‌فهمد، می‌تواند از آن استفاده کند.

مثل پریز مشترک است: به‌جای ساخت اتصال اختصاصی برای هر ترکیب، دو طرف قرارداد مشترکی را پیاده می‌کنند. گرهٔ وسط شکل، خود استاندارد است، نه یک سرویس مرکزی اجباری. نسبت تعداد اتصال‌ها یک تقریب برای نشان‌دادن قابلیت استفادهٔ دوباره است، نه وعدهٔ حذف همهٔ کار اتصال.

MCP علاوه بر ابزار، می‌تواند منابع و الگوهای درخواست را هم معرفی کند. این درس فقط مسیر ابزار را دنبال می‌کند: برنامه به سرویس وصل می‌شود و فهرست قابلیت را می‌گیرد؛ بعد مدل می‌تواند ابزار را درخواست کند. کشف فهرست، خواندن دادهٔ اختصاصی یا اجرای عمل نیست.

یک نکتهٔ مهم: استاندارد بودن به معنی امن بودن نیست. MCP اتصال را ساده می‌کند، اما تصمیم اینکه کدام ابزار به کدام داده دسترسی داشته باشد، هنوز با شماست.
